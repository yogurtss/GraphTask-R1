## 二、候选技术链

| 候选链 | 证据 | 结论 |
|---|---|---|
| 问题/程序联合生成 → 有界执行 → 执行 gold → 认证任务 | C001–C005 | 当前最稳定的技术基础 |
| 解析/执行接口就绪度 → 门控语义前沿 → 分阶段奖励 | C006 | 较有辨识度，建议与主链绑定 |
| 独立 Questioner/Solver 适配器 → Q 先更新 → 准入 → 同轮 S 更新 | C007–C009 | 较有辨识度，建议作为组合核心 |
| 程序签名/文本新颖性/难度窗口 → 确定性归档 | C005、C008 | 适合从属层和系统状态保护 |
| 有界预算 + 步骤轨迹 + 结构化错误码 | C003、C004 | 适合执行安全与可审计从属层 |

1. `[TO CONFIRM]` 发明人、申请人、完成时间、首次公开/论文/代码发布/演示日期。
2. `[TO CONFIRM]` 是否存在尚未提交仓库的实验结果，能够证明相对 prompt/tool 基线的准确率、成本或稳定性改善。

4. `[TO CONFIRM]` GraphScript 的必要最小算子集；哪些算子只是 KQAPro 实施例，哪些应进入一般化保护范围。
5. `[TO CONFIRM]` 接口就绪度是否必须采用乘积形式，还是允许其他单调组合函数。
6. `[TO CONFIRM]` 新颖性是否必须采用文本 trigram/Jaccard，还是应概括为结构与语义相似度联合度量。
7. `[TO CONFIRM]` “同轮消费”是否在所有生产部署中固定，或允许相邻子轮/微批次更新。

## 四、当前风险判断

- `program/code generation for KGQA`、`questioner/solver self-play`、`knowledge-graph grounded task generation` 均已有公开研究，不能单独作为宽泛创新点。
- 当前较值得保护的是各要素的**协同依赖关系**：执行认证 gold、接口门控前沿、独立双适配器、确定性归档以及同轮数据重建。
- 正式权利要求应由中国专利代理师结合检索结果审阅；本材料不应被描述为“可直接提交”。
